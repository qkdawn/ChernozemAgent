# 农情解读工作流审查（2026-10-24）

## 用户要完成的判断

针对一个已授权玉米地块和指定时段，回答哪里与田内其他区域不同、变化集中在哪段时间、多源证据支持哪些解释，以及哪项具体行动能区分这些解释。巡田记录可以缺省；缺少现场记录不能让所有分析退化为“先巡田再说”。

## 沿现有链路找到的问题

1. `CornSkillRunner` 按固定顺序执行计算工具，并非模型自主调查。固定执行本身有利于首个真实任务稳定交付，但不能描述成模型已能按发现补调工具。
2. `analysis-brief.ts` 通过 TypeScript 分支拼写正文；增加七个章节没有增加比较证据。低值区默认先查低洼与排水，甚至不要求有对应地形和降雨证据。
3. `analysis-brief-editor.ts` 原先只允许改 headline、overview、reasoning、uncertainty，不能改 document。它还按数字及判断词出现次数、汉字白名单拒绝改写。模型实际是受限润色器。
4. 模型原先收到的是预写摘要与动作，没有完整时序、分区指标和多源计算结果。它无法发现输入没有提供的关系；加长提示词不能补出地块证据。
5. 计算工具的 summary、limitations、nextActions 与正文模板共同注入“等待、核查、不能判断”。限制还会在各章节被重复，掩盖已经能够形成的发现。
6. 成果仓储已存在，支持按任务列举和按结果 ID 读取。无需另建成果平台或再复制一套人工 key_facts。现有模型运行时禁用工具，尚无调查—写作—补读的闭环。
7. 实际模型会话还继承了仓库里的 coding `AGENTS.md`：旧的默认工作目录位于仓库子目录，模型除了农情数据还读到开发规程。默认目录已移到系统临时目录的独立空工作区，避免将本仓库开发指令注入生产农情写作。显式配置目录时仍须选用独立目录。

## 改动边界

确定性代码继续负责授权、空间范围、指标计算、质量状态和专业发布边界。模型负责在这些事实之上比较、解释和组织有针对性的正文；后端不再规定每个判断必须用哪些词、每句话必须保留哪些汉字，也不规定必须写满七章。

现有发布入口已改为 `analysis-brief-writer.ts`：模型直接消费本任务已有的领域结果，生成文档而不是编辑模板。保留结果 ID、字段引用与地图分区关联；来源校验与文本语义评价分开。引用存在只证明可定位，不证明整句话正确。原来的汉字白名单和数字/关键词出现次数校验已删除，确定性七章正文也已删除。

文档生成失败或未配置模型时，保留简短计算摘要并明确标识状态。模型的 `reviewRequired` 和发布门对常见执行用语的识别可以追加专业复核，不能解除原工具的复核状态。这些机制不保证识别所有自然语言处方：诊断、数字和处方语义仍需独立的主张级评测与专业发布流程，不能宣称已有自动保证。

连接实测：已有旧地块结果读取成功，但配置的模型端点在直接连接 /models 和 /responses 时均返回连接超时。先后 90 秒和 180 秒的写作尝试均未交付模型文档。当前验收证据是契约、引用、状态和回归测试，不能写成真实模型输出已验收。

本次不新增自主工具协议、不改写采集或遥感计算、不强制获取巡田记录、不把知识材料当成该地块的观测事实。动态补读成果、针对发现调用补充计算和知识检索属于后续运行时能力，需要真正接入受控工具后才能称为已实现。

## 验收口径

- 模型实际收到有效观测、变化、分区及来源数据，而非七章底稿。
- 模型能够改变章节、比较对象、论述和非处方性的核查建议；不受原文字符或词频限制。
- 不接受跨任务、跨地块、不同边界版本的结果引用；无数据保持显式缺失。
- 文档能回溯到实际结果及字段；伪造引用不能发布。
- 药肥水处方仍需专业复核；模型失败保留计算结果，并明确标识未完成 AI 解读。
- 测试分别报告契约与引用正确性、主张是否有证据支持、农业解释是否有价值。单元测试通过不等于真实地块或专家评测通过。

## 真实旧地块的待核对项

## 2026-10-25 对真实文档的批判性复盘

真实任务 `aca17f7b-34e2-442f-977b-7f0b63b56c0f` 的数值和引用已经通过逐项核对，但语言交付仍没有达到“拿来做一次田间决策”的标准。问题不在于证据太少，而在于调查阶段没有先形成决策问题，写作阶段因此把“证明边界”当成了主要内容。

1. **结论层级倒置**：正文先解释相对分区、窗口外基线、覆盖比例和不能证明的事项，用户要做的判断被埋在后面。限制是必要的，但应该只保留会改变当前选择的那一条。
2. **工具结果没有转成选择**：天气、雷达和地形被读取，却没有与偏弱区形成空间交集；它们只能作为背景段落，不能改变“先看哪一块”。调用次数增加了，决策信息没有增加。
3. **行动缺少分支**：`复盘资料`、`等待下一期影像`、`如有条件核查` 没有指定当前第一动作，也没有说明现场结果怎样让判断转向。用户仍需自己完成最后一次推理。
4. **相对分类被防御性重复**：同日偏弱、跨期相对类别和绝对变化在多处反复解释，形成审计说明的语气；一次方法说明后应直接给出区域差异和优先级。
5. **技术词先于农情意义**：NDVI、NDMI、RECI 和轨道日期连续出现，普通用户需要自行翻译“这意味着先查什么”。指标应作为证据附着在区域判断之后。
6. **输出契约缺少决策字段**：原 `actions` 只有动作、目的和清单，没有“结果如何改变判断”；`document` 章节数量和顺序也没有面向决策的默认结构，因此模型容易写成审计报告。
7. **界面隐藏了行动**：当模型生成 `document` 时，前端原先只显示文档，不显示 `actions`、`overview` 和 `reasoning`。即使模型给出了可执行动作，用户也看不到。

本轮将写作提示词升级为 `analysis-brief-writer-v4`：先建立“当前决定—优先区域—区分证据—第一动作—A/B 分支”的内部框架，只调用会改变选择的工具；文档默认按“当前判断、区域差异与依据、先做什么、结果如何改变判断”组织，新增可选的 `decisionEffect` 字段。前端现在始终先呈现判断、依据和行动，再展开完整文档。这样保留了数据和引用的后端边界，同时把模型的自由度用于比较、解释和行动组织。

这次修订仍不能替代真实模型复跑和农学专家盲评。验收时应重点检查：第一屏是否明确一个优先区域和第一动作；每个动作是否有可观察的 A/B 分支；天气、雷达或地形是否真的改变了优先级；限制是否只出现一次；以及用户能否只读摘要和行动完成一次现场安排。

### writer-v4 实跑对照

用同一授权地块和相同历史窗口重新运行的任务 `6667aeb7-4592-416e-bdc9-3ee10992332a` 已生成模型文档。它把约 5.05 公顷主弱区列为第一优先区，给出 3 个代表点加 1 个近平均对照点，并把“缺株/黄化”与“湿痕/根系受损”连接到不同的后续判断；没有为天气、雷达和地形制造未计算的空间交集。这证明提示词改动确实改变了输出结构，而不是只改变标题。

这次 v4 输出仍暴露出三个需要继续压缩的点：生育期段落曾加入没有知识引用支持的“可能影响群体功能”推断；窗口外基线和数据缺口在多个段落重复；模型把“专业复核”保守地标成了 `reviewRequired`。因此提示词已升级为 v5，明确阶段只作时间背景、限制只说明一次，并把专业复核与处方执行分开。任务 `60b8e16b-8e4a-45d6-9b53-e5d9cd076829` 的 v5 实跑已验证：第一动作是主弱区与高于平均区对照核查，动作带有水分/根系、营养、群体差异三类分支，正文没有把窗口外基线写成窗口内连续观测。另修正了“核对排水、灌溉和根系环境”被误判为处方的发布门规则，并加入回归测试。
