# 农情调查与写作优化（2026-10-25）

## 当前迭代的交付目标

让同一个玉米农情分析过程围绕用户问题读取已保存的地块证据、比较区域和时段、按需补读知识及调用受控计算，再形成带可定位引用的自然语言文档。缺少巡田记录不阻止遥感分析；计算失败不作为田况正常，知识规律不作为该地块实测。

## 执行顺序与完成证据

1. **成果与知识按需读取**：复用 Codex 原生 MCP 和现有结果仓储。模型先收到当前任务与成果目录，可读取本任务字段和检索具备来源、版本、适用范围的知识。跨任务、跨地块、边界不匹配和未发布知识被拒绝；集成测试通过。
2. **调查与写作可以回到计算**：仅注册当前任务允许的领域计算工具。执行后的结果先进入原成果仓储，再供阅读和文档引用；不创建临时事实 memo 或自制工具协议。无资产或计算失败返回明确结果，不把失败升级为原因判断。
3. **文档与证据一起交付**：模型自主比较、解释和组织正文；事实与知识引用分别可解析，引用的计算版本和知识原文随任务保留。后端继续控制空间、质量和专业发布状态，不恢复字符、词频或固定章节限制。
4. **验证是否真正回答问题**：分别检查对象、日期、单位、引用支持、同日/跨期区别、冲突证据、无巡田记录、缺测、失败及专业复核。契约测试、真实模型结果检查与农学专家评测分开记录，不创建综合质量分。
5. **真实旧地块验收**：核对历史比较范围，使用原地块运行新链路；验证界面中的长文、来源、任务进度和失败状态。若模型服务仍不可达，保留已通过的工程证据，真实输出验收保持未完成。

## 实施约束

- 现有确定性工作流可以继续完成首轮计算；本次补上按需调查，不把固定链路称作自主规划。
- MCP 仅是原生工具通讯，业务上下文和持久化结果由领域模块拥有；不重建 Harness、任务平台或知识平台。
- 网络模型端点、原文许可、地块观测及已有用户修改按当前实际状态核对，不把上一次失败或测试通过当作本次事实。

## 本轮实施与验证记录

### 已完成的工程改造

- `analysis-evidence.ts` 复用现有成果库，按任务、地块和边界绑定读取范围；按需计算先保存再返回，并复用同一任务已运行的结果。
- `analysis-evidence-mcp.ts` 使用 MCP SDK 的原生服务端和 HTTP handler。每次文档分析开放一个带随机令牌的 loopback 端点，结束后关闭；Codex SDK 自行处理工具通讯，没有自制 JSON 调用循环。
- 文档生成输入改为任务和成果目录。模型可以读字段、查原文、补调证据计算；不再把整份上游结果正文被动注入，也不传确定性 envelope 的预写摘要和动作。
- 生产装配将相同的成果仓储与已配置知识检索注入文档分析。`AnalysisBriefPublication` 同时交付正文和新增成果，任务重开后仍保留补算与知识记录。
- 发布时核对引用字段存在、非空且已读取。知识原文和地块观测分别展示出处；普通知识不能替代该田观测。专业复核状态保持独立。
- 本地预览已更新，原地块历史任务的全部 `analysisResults` 与更新前逐项比较一致；移除的是旧七章模板文档，历史影像与计算值没有改变。

### 真实运行发现的语义问题与修订

完整数据库链路的首份模型正文已生成，但人工主张核对发现：将占登记地块总面积的 32.1% 错写成占有效观测面积，并将窗口外的 7 月 16 日基线写为窗口内观测。该份正文不算通过验收；原始运行保留在本地忽略产物中。

修订优先进入数据契约：长势汇总新增 `observationWindow`，区分请求窗口内日期和窗口外比较日期；`areaBasis` 明确登记地块总面积及比例分母。对应已知日期与面积用例纳入回归。writer-v3 只补充面向种植户的中文区域称谓，机器分区引用保留在 `zoneRef`；没有改成固定章节或字数模板。原生调查整体允许六分钟，超时取消与计算摘要降级仍保留。

本地 API 已切回正式 PostgreSQL 装配，任务及成果随真实执行保存，供知识服务按同一任务 scope 检索。先前内存预览未保存新任务，知识服务因此返回 `knowledge_scope_unavailable`；这不是“没有相关知识”的同义状态。原历史任务未被重写。

## 原生调查入口契约

权威 schema 在 `analysis-evidence-mcp.ts`，可补算工具集合与语义在 `analysis-evidence.ts` 的 `EVIDENCE_TOOLS`。

| 入口 | 前提与领域结果 | 失败和复用 |
| --- | --- | --- |
| 成果目录 | 当前会话已绑定任务，返回成果 ID、类型、范围、来源、版本及可读字段 | 不暴露其他任务或边界成果 |
| 成果读取 | 持久化结果 ID；可选 result 内的 RFC 6901 路径 | 不存在或越界拒绝；缺测保留 null 和状态 |
| 证据计算 | 当前任务已注册工具；模型不提供 taskId、供应商配置或文件路径 | 已有计算直接复用；新结果先保存，失败不变为观测事实；耗时和资源由对应计算工具决定 |
| 知识检索 | 已配置知识端口；模型只提供问题 | 复用同任务同问题已保存检索；保存索引版本、原文和出处；无匹配与不可用保持不同状态 |

最小可执行测试见 `apps/api/src/analysis-evidence.test.ts`；正文、已读引用和新增成果交付测试见 `analysis-brief-writer.test.ts`。令牌只交给原生 MCP 客户端环境，不写入模型 prompt、任务正文或业务日志。
